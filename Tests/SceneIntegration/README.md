# Shared UI and Background Audit

Run from the project root in PowerShell:

```powershell
./Tests/SceneIntegration/Check-References.ps1
dotnet run --project Tests/BattlePlayback/BattlePlayback.Tests.proj
```

The read-only PowerShell audit checks local fileID references in the current
exploration scene, battle scene and two shared UI prefabs. It also checks required
menu bindings, three party slots, nested save-page source IDs, scene-specific
player/controller overrides, the keyboard UI module and active background root.
It recognizes the relevant Unity text serialization fields; it is not a general
YAML parser or a replacement for Unity's asset importer. External art references
and arbitrary future prefab variants are not exhaustively validated.

The playback tests cover background selection and session lifetime with Unity
API substitutes. Neither command modifies scenes, prefabs or player saves.

## Final Unity Checklist

1. Open the exploration menu: Esc toggles it and restores movement/time; party,
   save/load and confirmation pages preserve their return focus with Z/X.
2. On a test copy of a map, bind that map's player/controller to the shared Canvas.
   Opening the menu must pause that player; saving must record that map/position.
3. Assign distinct art prefabs A and B to two maps. Enter battle from each and
   confirm the correct background, with no previous-map instance remaining.
4. Restart mid-battle and Retry after defeat: the originating map's background
   must remain. Return to title/load another map must not reuse it.
5. Assign a default on BattleEnvironmentRoot. A map without an assigned background
   and a directly opened battle must use it; with both unset, battle still works.
6. Check the background's placement, camera framing, layers and UI/actor visibility.

Currently only one exploration scene exists and both background fields are empty.
Two-map rendering and real art validation remain pending; no replacement artwork
or extra production map is generated by these checks.
